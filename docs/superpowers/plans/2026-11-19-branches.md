# Şubeler: Uygulama Planı

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Bir stüdyonun birden çok şubesi olabilsin; her grup bir şubeye ait olsun, yönetici şubeleri panelden yönetsin, üye derslerin şubesini görsün.

**Architecture:** Yeni `branches` tablosu ve `groups.branch_id` (yaklaşım A). Dersin şubesi her zaman grubundan okunur. Bir grubun başka stüdyonun şubesine bağlanması birleşik yabancı anahtarla veritabanında engellenir. Arayüzdeki şube öğeleri yalnızca çok şubeli stüdyoda görünür.

**Tech Stack:** Node.js, Express 5, PostgreSQL (`pg`, numaralı SQL migration), React 19 (Vite), Node test runner, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-19-branches-design.md`

## Global Constraints

- Çok şubeli stüdyo = açık şube sayısı > 1. Şube öğeleri yalnızca o zaman görünür ("Şubeler" ayar bölümü hariç).
- Otomatik ilk şubenin adı: `Merkez`.
- Şube adı 2–60 karakter, boşluklar sadeleştirilir; adres en fazla 300 karakter; `maps_url` yalnızca `https://` ile başlar.
- Aynı stüdyoda aynı ad (büyük/küçük harf duyarsız, kapalılar dahil) iki kez olamaz.
- `studio_settings.makeup_other_branches` varsayılan `true`. Mevcut ayarların hiçbiri değişmez.
- Hata kodları: `BRANCH_NOT_FOUND` (404), `BRANCH_CLOSED` (400), `BRANCH_HAS_GROUPS` (409), `LAST_BRANCH` (409), `BRANCH_NAME_TAKEN` (409), `INVALID_MAPS_URL` (400), `INVALID_BRANCH_NAME` (400), `OTHER_BRANCH` (409, "Bu ders başka bir şubede.").
- Görsel yenileme yok: yeni alanlar mevcut bileşenlerle (`Admin.module.css`, `Button`, `TextField`) eklenir.
- Kod yorumları ve kullanıcı metinleri Türkçe; koda gerçek stüdyo adı, şehir ya da şube adı yazılmaz (testler ve demo verisi "A Şubesi", "B Şubesi" gibi genel adlar kullanır).
- **Commit'leri Pınar yapar.** Her görevin sonunda commit mesajı önerilir; mesajlarda ortak yazar (`Co-Authored-By`) ya da araç imzası satırı olmaz.
- Her görevden sonra özel günlüğe kayıt: `~/Documents/02 Projeler/studio-booking-notes/PROJE_GUNLUGU.md` (repoya girmez).

**Testleri çalıştırmak (PostgreSQL açık: `docker compose up -d`):**

- Tümü: `cd server && npm test`
- Tek dosya: `cd server && npm run pretest && DB_NAME=studio_booking_test BASE_DOMAIN=localhost BCRYPT_COST=4 node --test test/<dosya>.test.js`
- İstemci: `cd client && npm run lint && npm run build`

## Review Focus

- Şubesi kapatılan son açık gruptan sonra şubeyi kapatıp yeniden açmak: grup sayısı, `branchCount` ve "tek şubeli" görünüm doğru güncellenir. Test: Task 2 (`close then reopen updates branchCount`).
- Ayar kapalıyken grup değiştiren üye: telafi listesi dersin tarihindeki grubuna göre süzülür (geçişten önceki günler eski şube, sonraki günler yeni şube). Test: Task 5 (`own branch follows the group on the session date`).
- Gövdede `branchId` olarak metin, negatif sayı ya da `null` (çok şubede): veritabanı hatası değil `400`/`404`. Test: Task 3 (`invalid branchId values are rejected cleanly`).
- Şube adı yalnızca harf büyüklüğüyle farklı ("merkez" / "Merkez"): `409 BRANCH_NAME_TAKEN`. Test: Task 2.
- Bir şubeye adres girildikten sonra diğer şubelerin adresi boşsa: site yalnızca adresi olan şubeyi adresiyle, diğerlerini yalnızca adıyla gösterir; `site.json` adresine dönülmez. Test: Task 4 (`site uses branch addresses once any is filled`).

  - Yardımcı `defaultBranchId(studioId) -> id` (`helpers.js`).

- [ ] **Step 1: Başarısız testleri yaz** (`describe('branches schema')`)
  - `createStudio opens a Merkez branch and groups belong to it`: `createStudio()` sonrası `SELECT name FROM branches` → `['Merkez']`; `createGroup` ile açılan grubun `branch_id`'si o şube.
  - `a group cannot point to another studio's branch`: A'nın grubunu `UPDATE groups SET branch_id = <B'nin şubesi>` → hata kodu `23503`.
  - `branch names are unique per studio, ignoring case`: aynı stüdyoda `Merkez` ve `merkez` → `23505`; başka stüdyoda `Merkez` serbest.
  - `maps_url must be https`: `http://x` → `23514`; `https://maps.example.com/x` geçer.
  - `makeup_other_branches defaults to true`.

- [ ] **Step 2: Testin başarısız olduğunu gör.** Beklenen: `relation "branches" does not exist`.

- [ ] **Step 3: Migration'ı yaz.** Sıra: `branches` tablosu, kısıtlar (`UNIQUE (id, studio_id)`, `(studio_id, lower(name))` benzersiz index, `name` uzunluk, `address` ≤ 300, `maps_url ~ '^https://'`); her stüdyoya `Merkez`; `groups.branch_id` boş ekle → her grubu kendi stüdyosunun `Merkez`'ine bağla → `NOT NULL` → `FOREIGN KEY (branch_id, studio_id) REFERENCES branches (id, studio_id)`; `studio_settings.makeup_other_branches boolean NOT NULL DEFAULT true`.

- [ ] **Step 4: Stüdyo açan yolları uyarla.** `helpers.js`: `resetDb` `branches`'i de boşaltır; `createStudio` `Merkez`'i açar; `createGroup` `branch_id` yazar. `createAdmin.js`: yeni stüdyo açarken `Merkez`'i de aynı transaction'da açar. `seedDev.js`: demo dosyası `branches: [{ name, address? }]` verirse onları, vermezse `Merkez`'i açar; grup tanımındaki isteğe bağlı `branch` (ad) alanıyla eşleştirir, yoksa ilk şube.

- [ ] **Step 5: Doğrula.** `cd server && npm test` → yeni testler ve mevcutların tümü geçer.
